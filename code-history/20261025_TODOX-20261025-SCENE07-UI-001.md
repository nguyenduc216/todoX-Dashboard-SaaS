## Findings and behavior

Legacy/V2 explicit-operation visibility previously checked only generation/active-job/submit blocker. A failed current job with a provider task but no head/blocker could therefore lose the appropriate action. Both now reuse `SceneVideoUiState.RequiresExplicitOperation`, including failed owned attempts and provider identities on either the job or version. Playback selection remains separate from the current operation. The backend read model still excludes superseded historical jobs.

Important retry limitation: `RetrySceneVideoAsync` formerly enqueued a new batch/child with the old logical/version identity; `SceneVideoRenderHandler` calls TryBind, which cannot transfer a version already owned by another job, and the canonical ownership guard refuses that transfer. No task ID alone is therefore insufficient evidence that this Legacy retry path can work. Current owned failed attempts keep **Retry video** disabled with a specific reason and expose **Tạo lượt video mới** through existing Supersede V1. No new same-job resume or ownership-transfer API was invented. A backend-authorized old-operation retry path is not added by this change.

The Legacy media-frame retry now chooses safe retry vs explicit Supersede rather than the generic render handler. The shared Supersede button saves dirty Legacy draft state before reading consent, retains existing idempotency/acknowledgement behavior, reports the new job ID and reloads state/polling. Provider identities also trigger the unknown-outcome cost warning. Backend draft/activate, generation fences, source-image choice and durable submit policy remain unchanged.

Legacy and V2 desktop/mobile expose **Tạo ảnh / Tạo lại ảnh** below the image. Existing scene-image activity prevents duplicate actions; a failed video does not lock image rerender. Shared-reference mode explains why a separate scene image is disabled; no shared image/config is changed automatically. Both paths retain their existing canonical immutable image version/job pipeline. V2 polls the existing shell reload while an image/current video operation runs and cancels polling on disposal. Sanitized application error codes/messages omit raw provider/transport diagnostics.
