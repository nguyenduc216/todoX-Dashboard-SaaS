## Changes

### Canonical prompt source

- `HydratePromptFromActiveAsync` reads `ServicePromptGenerationDto.UserInput`
  only. Removed the `LooksLikeJson` heuristic and `OriginalPrompt` fallback.
- Baseline (`_baselineInput` / `_hasBaseline`) is captured on hydrate and is
  advanced only after a *confirmed* reload of the persisted `user_input`
  (`WaitForActiveGenerationAsync` + `outcome.Result.GenerationId`).
- Missing/unloadable active generation surfaces an honest empty-state message;
  it is never reconstructed from generated content.

### Dirty-aware Generate

- New pure helper `RVideoPromptBaseline` (CRLF/CR -> LF normalize, `IsEmpty`,
  `AreEqual`, `IsDirty`). `IsDirty(working, baseline, hasBaseline)`:
  - empty/whitespace working -> not dirty;
  - no baseline yet + non-empty working -> dirty (first generation);
  - otherwise ordinal compare after newline normalization.
- `CanGenerate = !_generating && IsDirty(...)`;
  `CanGenerateFirstTime = !_generating && !IsEmpty(_workingInput)`.
- Typing (`HandleWorkingInputChanged`) is local-only; it performs no server write.

### References (Upload / Character only)

- `InputReferences` projects only `Project.UploadedCharacterUrl` OR
  `SourceImageUrl` (Upload) plus the canonical character settings snapshot
  (Character). Scene static images are intentionally not projected.
- Upload icon uses `Icons.Material.Filled.Upload` over a hidden `InputFile`
  (`UploadReferenceAsync`) persisting via `IMediaFileService.SaveAsync`.
- Character icon (`Icons.Material.Filled.People`) opens
  `RVideoCharacterPickerDialog` (vertical, scrollable, `HashSet<long>`
  multi-select, `MaxSelectable` guard; Cancel performs no mutation; confirm
  returns `DialogResult.Ok(List<long>)`). Single-character limit
  (`MaxCharacterReferences = 1`) enforced for the current canonical contract.
- All reference mutations funnel through
  `RVideoJobUpdateHelper.BuildSafeUpdate(..., settingsOverride, sourceImageUrlOverride)`.

## Continuation 2026-10-08 (B) — duplicate top heading, wrapper leak, reference duplication

### Why the previous report did not match the observed UI

The prior continuation optimised the reference **controls** but three defects remained in the
rendered route. Each is a real implementation gap, traced to a concrete file:line, NOT a browser
cache or stale deploy:

1. **Duplicate top job heading** — `TodoX.Web/Components/Pages/RVideo/RVideoV2Shell.razor:13-38`
   (`<div class="rv2-header-top">`) rendered a large job title + edit icon + id/service/status meta
   row ABOVE the THÔNG TIN / XEM TRƯỚC tabs, on top of the editable "Tiêu đề" field inside the
   Information tab. The previous report only touched the Info component and never removed this block.

2. **Wrapper ("SOURCE CONTENT:") in the textarea** — root cause is on the *read* path, not the
   component: `TodoX.Web/Services/VideoRender/RVideoPromptGenerationAction.cs:48-53` builds the
   assembled agent input (`PromptAssistantEndpoints.BuildAgentInput` → "CONTENT MODE: … SOURCE
   CONTENT: …"), and that assembled string is what `ServicePromptAssistantService.PersistAndReturnAsync`
   stores into `user_input` (`ServicePromptAssistantService.cs:345`). The legacy route already knows
   this and unwraps it (`RenderVideoJobs.razor:4822` calls
   `PromptAssistantEndpoints.ExtractUserInput(generation?.UserInput)`), but V2 Info read
   `ag.UserInput` verbatim. The earlier "textarea only shows user content" claim assumed `UserInput`
   was raw; it is not for generations produced by this pipeline.

3. **Reference duplication** — `RVideoV2Info.razor` `InputReferences` (old lines 334-350) added an
   Upload card when `SourceImageUrl`/`UploadedCharacterUrl` was set **and** a second Character card
   when `CharacterMode != None && !SkipCharacter`. An uploaded reference sets BOTH (SourceImageUrl +
   CharacterMode=Upload + snapshot), so the same image was projected twice (count = 2).

### Changes actually made

- `RVideoV2Shell.razor`: removed the entire `rv2-header-top` title block (title + edit icon +
  id/service/status meta + desktop/mobile header actions). Kept the back affordance, the 3 tabs and
  the mobile tech bar; moved the back button beside the tabs in a compact `rv2-nav-row`. Removed the
  4 now-dead computed properties (`DisplayTitle`, `JobIdShort`, `ServiceLabel`, `StageLabel`).
- `RVideoV2Shell.razor.css`: replaced the heading/meta/title rules with `.rv2-nav-row` +
  `.rv2-nav-row .rv2-tabs`.
- `RVideoV2Info.razor`: added `ResolveRawUserInput(stored, fallback)` and routed all three hydrate
  paths (`HydratePromptFromActiveAsync`, post-generate confirm, `HandleHistoryAsync`) through it. It
  uses the **verified inverse** `PromptAssistantEndpoints.ExtractUserInput` (same contract the legacy
  route uses, with existing unit tests in `PromptAssistantEndpointsTests`). A value that is a
  recognized `CONTENT MODE:` wrapper but cannot be unwrapped yields the fallback (honest empty state);
  a value that is not a recognized wrapper is returned verbatim (no user content stripped, no regex
  heuristic).
- `RVideoV2Info.razor`: rewrote `InputReferences` to a **single-slot** projection (Upload XOR
  Character) that returns early on the character slot, so the same image can never produce two cards.
  The projection source now matches `ActiveReferenceSource`, so the highlighted icon always matches
  the single projected card.
- Housekeeping: two stale comments that still described the Upload control as a `<label>` were
  corrected (it is a `<span role="button">`).

### Prompt provenance summary

- Stored `user_input` for generations from this pipeline = assembled agent input (wrapper).
- Raw source recovered only via the verified inverse (`ExtractUserInput`); otherwise honest empty
  state. No heuristic JSON detection, no keyword trimming, no history/DB rewrite.
- `Raw source (user-entered)` and `assembled agent input` remain separate per the existing contract.
### Reference state summary

- Exactly one active source: Upload XOR Character. Count is 0 or 1 only.
- Upload success sets `SourceImageUrl` + `CharacterMode=Upload` snapshot; Character confirm sets
  `CharacterMode=Library` + snapshot. Both go through `RVideoJobUpdateHelper.BuildSafeUpdate` with a
  settings override that preserves all other settings. No physical file is deleted on switch.
- Reload re-derives the single reference + source label from the canonical settings/project fields.
